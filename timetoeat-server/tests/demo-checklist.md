# 演示数据验证清单

导入命令（后端目录）：`node scripts/seed-demo.cjs`。直接写入当前 Docker MySQL；使用事务，重复执行不会重复建用户、好友、菜品或消息，也不会重置消息已读状态。已删除的原创菜不会恢复。公共菜关联被手动删除后重跑会补回。

默认以 `tester-001` 测试。登录后切换一次底部标签或重新编译，以刷新数据。

| 测试账号 | 昵称 | 与 tester-001 的关系 / 场景 |
|---|---|---|
| tester-001 | 测试用户（保留已有昵称） | 自己有 3 道原创菜和 2 道公共菜 |
| tester-002 | 小林 | 已是好友；4 道菜，60 条聊天，验证历史翻页、四类消息和未读 |
| tester-003 | 阿哲 | 已是好友；4 道菜，双方点菜与催饭 |
| tester-004 | 小雨 | 已是好友；3 道菜，已读消息 |
| tester-005 | 小美 | 尚非好友；搜索“小美”后添加，查看其 2 道菜并开始聊天 |
| tester-006 | 新朋友 | 已是好友；无菜品、无消息，验证空页面 |

1. **登录与切换**：在“我的 → 切换账号 / 退出登录”使用表中的账号；同一账号重复登录不会新增 users 行。验证首次注册可另输入 `tester-007`。
2. **我的菜品**：查看现有菜，新增任意菜；可删除“测试可删除菜品”，刷新后确认不再出现。
3. **好友与搜索**：查看 4 位好友；搜索“小美”并添加；搜索不存在的名字验证空结果。
4. **聊天四种类型**：小林会话中有文字、表情、想吃的菜、催饭；点击菜品、催一下、表情按钮和输入框继续发送。
5. **分页**：小林会话有 60 条消息，初次加载 50 条，点击“查看更早消息”加载其余 10 条。
6. **未读与已读**：初始 tester-001 收到小林 2 条、阿哲 1 条未读。打开对应聊天后清除未读；切换到对方账号，查看已读回执。打开页面会改变已读状态，之后不再等于初始值是正常的。
7. **空状态**：打开“新朋友”会话验证暂无菜品和暂无聊天。
8. **删除后的历史**：删除自己曾被对方点过的“可乐鸡翅”，历史菜品卡片仍保留名称；对方再次催这道已删除的菜会得到明确错误。
9. **持久化与失败处理**：重新编译后数据仍在；临时停止 API 后发送文字会报错且保留草稿，恢复 API 后重试。

共 66 条演示消息；账号仅用于本地测试。已有 QA 数据和其他账号数据不删除、不覆盖。真实微信授权、真机网络、支付不属于这批假数据能验证的范围。
